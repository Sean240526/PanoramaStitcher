# 基于 ORB 特征的全景图像拼接系统：技术报告

**作者**：孙世豪
**日期**：2026年8月21日
**版本**：v1.0
**代码仓库**：https://github.com/Sean240526/PanoramaStitcher


## 1. 引言

全景拼接就是把几张有重叠部分的照片合成一张宽幅图。手机上的全景模式、VR 里的场景拼接、自动驾驶的环视系统都会用到这个技术。

2007 年 Brown 和 Lowe 发了一篇论文，把"特征提取 → 匹配 → 配准 → 优化 → 融合"这条路走通了，后面做拼接的基本都绕不开它。我这个项目就是照着这个思路，用 C++ 和 OpenCV 写了一个能跑的全景拼接程序，主要面向 3-5 张图的轻量级场景。


## 2. 论文里是怎么做的

Brown 和 Lowe 那篇论文的方法分五步：

**（1）特征提取**

用 SIFT 找特征点，SIFT 对缩放和旋转不敏感，每个点用一个 128 维向量表示。

**（2）特征匹配**

用 k-d tree 加速搜索，然后用 Lowe's 比率筛掉模糊匹配（论文里用的阈值是 0.8）。

**（3）几何配准**

用 RANSAC 算一个 3×3 的单应性矩阵 H，把两张图的坐标对齐。

**（4）全局优化**

用 Bundle Adjustment 同时优化所有相机的参数，把累积误差分摊开。

**（5）图像融合**

用多频段融合（Multi-Band Blending）处理拼接缝，高频细节在小范围融合，低频颜色在大范围融合。


## 3. 我是怎么做的

我没有完全照搬论文的方法，而是根据我的场景做了一些调整。

**（1）特征提取：ORB**

论文用 SIFT，我用 ORB。ORB 没有尺度不变性，但速度快很多，拼 3-5 张图够用了。我固定取 250 个特征点。

**代码位置**：`src/stitch.cpp` 中的 `detectAndCompute`

**（2）特征匹配：BFMatcher + Lowe's 比率**

特征点少，暴力匹配也跑得动，所以没用 k-d tree。Lowe's 比率阈值我设的是 0.75，和论文差不多。

**代码位置**：`src/stitch.cpp` 中的 `knnMatch` 和筛选逻辑

**（3）几何配准：RANSAC + findHomography**

这部分和论文一样，用 RANSAC 剔除误匹配，算 H 矩阵。重投影阈值设的是 3.0。

**代码位置**：`src/stitch.cpp` 中的 `findHomography(pts2, pts1, RANSAC, 3.0)`

**（4）图像融合：渐变融合（Gradient Blending）**

论文用多频段融合，我用的是渐变融合，重叠区域从左到右线性过渡。拼 3-5 张图时效果不错，代码也更简单。

**代码位置**：`src/stitch.cpp` 中的 `gradientBlend`

**（5）额外功能：自动排序**

论文的输入是无序图片，我也实现了这个功能。原理是算两两之间的匹配点数，匹配多的就是相邻的，然后从左到右排好顺序再拼。

**代码位置**：`src/stitch.cpp` 中的 `autoSortImages`


## 4. 我和论文的差异

| 对比项 | Brown & Lowe 2007 | 我的系统 |
|--------|-------------------|----------|
| 特征类型 | SIFT（有尺度不变性） | ORB（更快） |
| 匹配加速 | k-d tree | BFMatcher（暴力匹配） |
| 几何优化 | Bundle Adjustment（全局优化） | 逐张拼接（局部拼接） |
| 融合策略 | Multi-Band Blending | Gradient Blending（渐变融合） |
| 输入顺序 | 自动识别 | 自动排序 |

差异的主要原因是我只需要处理 3-5 张图，不需要应对 57 张图那种场景，所以省掉了全局优化和多频段融合这些复杂模块。

## 6. 总结

这个项目用 C++ 实现了一个轻量级的全景拼接系统，能自动排序、算变换、消接缝、裁黑边。核心逻辑是 ORB 找特征，RANSAC 算 H，渐变融合拼图。

跟 Brown 2007 比，整体框架一致，具体实现上根据 3-5 张图的场景做了简化。

后续如果想继续做，可以加多频段融合、支持更多图片、加个 GUI 界面，或者往视频拼接方向走。
